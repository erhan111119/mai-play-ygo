# 麦麦玩游戏王（Mai Play YGO）

让麦麦和群友开房间打一局游戏王，顺带能查卡、发卡图；插件自带一个面板，用来管卡组、看对局、给卡组写与练出牌脚本。

**平台：只支持 Windows**（对局内核 `ygopro.exe` 与出牌引擎 `WindBot.exe` 都是 Windows 程序；
别的系统上插件照常加载，但开房会被明确拒绝，只有查卡与发卡图可用）。

**当前版本：1.1.0**

## 功能

- **开房对打**：群里 `@麦麦 想打牌` 或 `/开房` → 起一局，把服务器地址与房间口令发到群里，群友用 MDPro3 / YGOMobile 连进来打；打完把胜负播报回群里（可关，也可交给模型润色）。
- **查房出图**：`/查房` 出一张棋盘图（双方 LP、回合与阶段、场上每张卡；里侧的只画卡背）。
- **卡组池**：`/加卡组 <卡组码>` 投稿（YDK / `ydke://` / 萌卡链接），可放进随机池让麦麦随机抽，也可固定一副。
- **百科检索**：查卡（中/日/英文名、效果、攻守、FAQ）与发卡图；卡图本地优先，缺了才走在线 CDN。
- **面板 + 训练功能**（**不在群里用命令**）：看卡组池、对局与日志，并在面板里发起四件事——
  卡组互打 / 编写脚本 / 卡组迭代 / 复盘优化。详见下面「面板与训练功能」。

## 安装

1. 把整个 `mai-play-ygo` 目录放进 `<MaiBot>/plugins/`；
2. `cp config.toml.example config.toml`（仓库只放模板，本机配置已 gitignore）；
3. 在 WebUI 插件页启用；
4. 确认自带的两个客户端在位：`python tools/setup_clients.py --check-only`（缺了用 `--from <你的 ygopro 环境>` 同步一份）。

## 配置（`config.toml`）

模板里每一项都写着默认值与作用，这里只说容易踩的：

**模型填的是"名字"不是"标识符"**。`[llm]` 的四个 `*_model` 要填宿主 `config/model_config.toml` 里
那个模型的 **`name`**（你随意命名的那个），**不是 `model_identifier`**（发给供应商的标识符）。
两者常常不一样（`name` 是你自己起的名字，`model_identifier` 是发给供应商的那个串），写标识符会被宿主拒掉
（`未找到名为 'xxx' 的模型`，插件会把原因原样记进日志与训练记录）。
**留空＝跟宿主的默认插件任务走**（宿主把插件的默认任务定为 `utils`，也就是 `[model_task_config.utils]` 那一组）；
`search_model` 是个例外——它没有"默认那只"可跟，留空就是**不联网**。

| 键 | 用途 | 要点 |
| --- | --- | --- |
| `summary_model` / `summary_timeout_ms` | 对局总结写成一段人话 | 哪只都行；超时默认 60 秒（思考型模型会先想一大段） |
| `decision_model` / `decision_timeout_ms` | 阻抗决策层问"该指哪只怪" | **必须不思考**（对手回合等待预算只有 15 秒）；等待上限按实测耗时配：1~2 秒档配 4000ms |
| `training_model` / `training_timeout_ms` | 推演 / 写脚本 / 复盘 / 写结论 | **必须不思考**：宿主单次调用有 30 秒硬超时，超时给 25 秒即可（给更大没用） |
| `training_script_max_tokens` | 写脚本时**每次调用**的输出上限 | 脚本分批写（每批 8 张卡），这个数决定"一批能写多细"；别超 8000 |
| `search_model` / `search_rounds` | 写脚本 / 迭代前**联网查资料** | `search_model` 填一只**带检索**的模型名（不是每只都能联网，详见 `docs/training.md`）、`search_rounds` 是让它自己查几次（默认 4）；留空＝不联网 |

其余几节：`[paths]` 默认指向插件自带的 `clients/`（相对路径，整个目录拷到哪都能跑）；`[duel]` 只有群主要用的十项；
`[wiki]` 只有接口地址与超时；`[webui]` / `[training]` 管面板与训练。`summary_prompt` 支持
`{self_name}` `{report}` `{verdict}` `{winner}` `{turns}`，写错启动时直接报错。

**阻抗决策层**只在阻抗时点（对手回合 + 当前判定的是阻抗卡）让模型做两个决定，展开期一步都不问；
实测与判读方法见 `executors/README.md` §3.5。

## 面板与训练功能

面板随插件启动（默认 `http://127.0.0.1:17911/`；密钥取法见下）。**五页**：总览、卡组、对局、训练台、日志。

- **卡组页**：卡片栅格（卡图 + 卡名 + 随机池开关 + 每副牌自己的 AI 决策档位 + 它那份脚本），
  点开看分区卡表、加入/移出随机池、删除（内置卡组删不掉）。
- **对局监控页**：每 2 秒刷新，画双方整张牌桌（额外怪兽区 / 5 主怪兽区 / 5 魔陷含灵摆 / 场地区 + 三堆计数）。
  **只有怪兽区**给攻守（内核下发过当前值就用当前值，否则退回卡面数值并标注）；里侧的只画卡背。
- **训练台**四件事，都是"选一副牌 + 一句话"：

  | 任务 | 干什么 | 起对局 |
  | --- | --- | --- |
  | 卡组互打 | 选另一副卡组对打，两边各用自己那份脚本，逐局交替座位 | 会 |
  | 编写脚本 | 读卡文写 C# 出牌脚本并编译进 WindBot；分批写，所以第一次就写足量 | 不会 |
  | 卡组迭代 | 推演 → 写脚本 → 跟另一副牌打 → 按逐局战况说下一版改哪几个函数 → 再改一轮 | 会 |
  | 复盘优化 | 读对局记录 + 当前脚本的结构摘要/源码 + 那一局的决策日志，指出该改哪个函数/分支，并给可落地的补丁 | 不会 |

  每个任务跑完都会在记录里落一段**明文结果**（局数/胜负/胜率、脚本行数与处理函数数、补丁落地情况……）。
  写脚本要配 `paths.windbot_src_dir`（脚本是编译进 WindBot 的），没配时面板上会标成不可用。
  **细则与踩过的坑**（复盘的四层材料、补丁格式与落地语义、联网写脚本、擂台纪律）见
  [docs/training.md](docs/training.md)。

**密钥**：`api_key` 留空时按「环境变量 `YGO_WEBUI_KEY` → 自动生成」取，自动生成的写在数据目录的
`webui_key.txt`；也可以贴一次 `http://127.0.0.1:17911/?key=<密钥>`（会换成 cookie 并跳到干净地址）。
**面板怎么点都不会重启插件**（发起/停止任务、改设置、翻页都只是接口调用）；只有改动插件目录里的
`.py` / `_manifest.json` 才会重启插件运行时，正在打的对局会断——所以别在有对局时改代码。

## 指令

| 指令 | 作用 |
| --- | --- |
| `/开房` `/开局` | 开一局并把地址与口令发到群里 |
| `/查房` `/战况` `/局面` | 出棋盘图；其余房间再各报一段文字 |
| `/加卡组 <卡组码> [名字]` | 投稿卡组（**卡组码只能用指令导入**，模型不会自动识别） |
| `/卡组列表` `/卡组详情` `/删卡组` | 看池子 / 看详情 / 删投稿（`/删卡组` 是**管理员**操作） |
| `/加入随机` `/移出随机` `/随机池` `/固定卡组` | 随机池与固定卡组 |
| `/清空卡组` `/对局名字` | **只清本群的投稿** / 改对局内名字（都需操作权限） |

模型可调用的工具：`ygo_duel_start`、`ygo_duel_status`、`ygo_duel_stop`、`ygo_deck_list`、`ygo_card_search`、`ygo_card_image`。
卡组池是共享的：任何群看到的是同一份列表，谁都能用；`/清空卡组` 只清本群的投稿，`/删卡组` 是全局删除（所以要管理员）。
**「编号」就是 `/卡组列表` 里的那个序号**（内置卡组在前、投稿按加入顺序，从 1 起）：`/加入随机 <编号>`、`/固定卡组 <编号>`、`/卡组详情 <编号>` 以及 WebUI 面板上的 `#N` 都是同一个号（数据库主键不对外显示，编号会随删除重排）。

## 安全与边界

- 闸门默认监听 `0.0.0.0`，房间口令随机生成、由插件直接发到群里；建议只放行闸门端口（`listen_port`）。
- **面板默认只监听 `127.0.0.1`**，每个接口都要密钥。想对外就改 `0.0.0.0`，并保证端口不暴露在公网。
  密钥不写进仓库（`config.toml` 已 gitignore）。
- 出网请求都过 `duel/netguard`：只 http/https、只连公网地址（内网/回环拒绝）、重定向逐跳校验、响应体有上限。
- 只把"双方统计"交给模型做总结；聊天记录、用户 ID、密钥不外传。训练任务起的是自带 `tools/` 脚本，
  参数由面板表单拼成 argv（不是 shell 命令）。

## 目录与开发

```
plugin.py / wiki.py           # 插件主体（开房、卡组池、指令与工具）与百科检索
webui.py                      # 插件自带面板（零第三方依赖：http.server + 线程）
train/                        # 训练功能：记录库、任务执行器、写脚本、问模型那几块
duel/                         # 对局运行时：协议、局面、闸门、出图、决策层桥接
clients/                      # 自带的两个虚拟客户端（ygopro + WindBot）
executors/                    # 十份专属出牌脚本（C#）与安装说明
tools/ tests/ docs/           # 运维与实验脚本、测试、深入文档（出图与对局监视）
```

```bash
python -m pytest tests -q --asyncio-mode=auto                    # 测试
python tools/run_tests.py                                        # 同上，逐个文件跑（不用 pytest）
python tools/field_image.py --demo --render                      # 单独看查房出图长什么样
python tools/check_engine_data.py --ygopro-dir clients/ygopro    # 内核 / 卡库 / 卡脚本是否同源
python tools/brain_model_probe.py                                # 阻抗决策层：量各模型单次延迟（选 decision_model 用）
python tools/brain_channel_check.py                              # 阻抗决策层：起真房间验一次问答链路
python tools/pool_smoke.py                                       # 随机池逐副体检：脚本装对了没有 + 能不能打
```
