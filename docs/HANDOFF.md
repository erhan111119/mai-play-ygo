## 3. 工具（用错口径会得出假结论）

```bash
# 逐局"我方第 1 回合结束"（窗口含结束阶段）的场面 + 可选统计
python tools/plan_accept.py --log <log> --marker "杀手级" \
  --deck <这张牌的 ydk> --cards-cdb clients/ygopro/cards.cdb \
  --monster "锁缚龙 锁镰" --spell "完美世界 卡通世界" --grave "闪刀起动-交闪" --interrupt --hand "起手件"
```
* **`--marker` 要能出现在我方卡组的卡名里**（默认 `杀手级` 是给杀调的）：它靠"谁的场面 dump 里出现过这个片段"
  认我方进程；给一个不在任何卡名里的词（如 `--marker 杀调`）→ **每局都"认不出我方进程"→ 除零崩溃/全 0**。
  闪刀用 `--marker 闪刀` 可以（卡名里到处都是）。
* **`--monster/--spell/--grave` 是"整名字面匹配"**：`闪刀姬=零露`（等号！）、`锁缚龙 锁镰`（有空格）、

## 5. 这一轮踩的坑（别再踩）

1. **基类的兜底 SpSummon 会替"没有专属规则的额外怪"做决定**：`DoEverythingExecutor` 里
   `AddExecutor(ExecutorType.SpSummon)` 的谓词是 `DefaultNoExecutor`（**这张卡没有专属规则时才生效**）。
   「毁灭之黑魔术师」就是被它做掉的（替代召唤的代价选到代理师傅）。要给"有替代召唤条件"的额外怪都写专属规则。
2. **闸门写成 `!PlanActive()` ＝ 计划没识别时等于没有闸门**（杀调壶、魔女术连接怪都踩过）。
3. **`--marker` 不在卡名里 → 全 0（还会除零崩溃）**；**`--monster` 是字面匹配**：等号/空格/前缀都要照抄。
4. 连接素材由基类挑，**我们改不了它挑谁**——只能"不让它在这个场面做连接召唤"（场上不心疼的怪 <2 只就不放行）。
5. 统计某个效果"实际用了几次"比统计"场上还剩什么"更能看出链路（例：闪刀的双纽闪门）。
6. 编译与评测串行：评测跑着时编译会因 exe 被锁失败。
7. 6～12 局的 A/B 误差 ±30～40%，要下结论至少 20～30 局/格，**并且尽量同一洗牌 base**。
   ⚠ 更狠的一条（10-05 实测）：**n=30、同 build、同 seed，重跑也能差 3/30**（基类 `Rand.Next`）。
   所以 30 局只能"看方向"；判定顺位类改动要 **40 局 + 同 build 重跑一次当噪声基线**。
   另外：**"成功局有什么共同特征"不能反推"照那个特征改会更好"**——魔女术"出代理师傅的局都不过大魔女"
   就是幸存者偏差（那些局是大魔女素材不齐被跳过的），照它改顺位实测无收益。
8. **同一 seed 重跑也会浮动**：基类 `OnSelectOption` 用 `Rand.Next`（分支随机），
   同一 build、同一 seed 两次跑出 代理师傅 6/30 与 4/30——判改动要拿"同 build 重跑"当噪声基线。
9. **"第一回合没有战斗阶段"**（内核 `Duel.MainPhase.CanBattlePhase` 在第 1 回合为否）——
   凡是"打斩杀"的规则（多打一次、变身增强、打脸堆墓）都要用 `BattlePhaseAvailable()` 挡住，
   先手第一回合该做的是阻抗（下回合的康、把资源转进墓地、留在手上的解场件）。
10. **编译前先确认没有残留 WindBot 进程**：评测异常结束时 exe 可能被锁，
    MSB3027/MSB3021 会**静默地只更新 obj 不更新 bin**（`check_windbot_build.py` 仍报"一致 ✔"，
    你测的其实是旧版本）。`taskkill //F //IM WindBot.exe` 后再编。
11. **执行器优先级 = 规则在 `Executors` 列表里的顺序**（这条最值钱，0.21.85 闪刀就是被它卡住的）：
    `GameAI.OnSelectIdleCmd` 是 `foreach (CardExecutor exec in Executor.Executors)`，对每个 exec
    依次试 Activate → MonsterSet → Repos → **SpSummon** → Summon/SummonOrSet → SpellSet，
    **第一个命中的就执行**。而基类 `DoEverythingExecutor` 构造里注册的通用
    `SpSummon`/`Activate`/`SummonOrSet`/`SpellSet` 排在本类自己加的所有规则**前面**，
    其中 `SpSummon` 用的是 `AddExecutor(ExecutorType.SpSummon)` → 谓词是 `DefaultNoExecutor`
    （＝"这张卡没有专属 SpSummon 规则"）→ **任何没被点名的额外怪都会在这里被放行**，
    于是"每次主要阶段先做连接召唤/先盖牌"，把"先发动、再铺场"的链整条顶掉。
    修法：构造函数里先把基类那几条 `CardId == -1` 的通用规则 `Executors.RemoveAt` 掉，
    再按想要的优先级重新 Add（0.21.85 的顺序：专门规则 → 通召 → 通用发动 → 通用连接召唤 → Repos → 盖放）。
12. **同一张卡的"①触发"和"②起动"只能靠 `ActivateDescription` 区分**：
    `ShouldExecute` 在调谓词前会 `Executor.SetCard(type, card, desc, timing)`，
    谓词里能读到 `Card` / `ActivateDescription` / `CurrentTiming`；而 `GameBehavior.OnSelectEffectYn`
    把触发型效果的 desc 归一成 **-1**（原始 0/221），起动/连锁窗口的 desc 是它自己的说明 id。
    另外：`AddExecutor(ExecutorType.Activate, 卡号, 判据)` 的判据**同时也是**"可选触发效果
    （`～場合才能発動`）要不要应"的开关（`GameAI.OnSelectEffectYn` 拿同一批规则问一遍），返回 false 就是不应；
    但"必发"效果内核不问，别想用判据挡它。
13. **分支型效果的选项编码 = `卡号 * 16 + 脚本值 + 1`**（脚本值＝卡脚本 `aux.SelectFromOptions`
    表里第 3 列，1 起数；探针实测 慶典 1 → `6958567*16+2`）。基类 `OnSelectOption` 是 `Rand.Next`
