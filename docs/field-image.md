# 查房出图（`/查房` 的对局棋盘图）

> 2026-10-07 起：群里问 `/查房`，本流那个房间**发一张图**——双方 LP、第几回合与当前阶段、
> 场上每张卡（表侧用本机客户端的卡图、里侧画卡背）。
> 2026-10-08：排版改成**按 MD 局内**的样子（以用户给的 MDPro3 截图为口径），
> 卡面是**自绘的标准游戏王卡框**（中文卡名 + 等级星 + 立绘 + 类型行 + 中文卡文 + 攻守）。

## 长什么样

```
┌───────────────────────────────────────────────────────────────────────┐
│ 游戏王·当前局面  群「xxx」                        第 7 回合 · 主要阶段 2 │
├───────────────┬───────────────────────────────────────┬───────────────┤
│ 我方 LP 条     │  对手 魔陷行(5) + 场地                 │  对手 LP 条   │
│ 头像/名字/血条 │  对手 怪兽行(5)                        │  ◆ Turn/阶段  │
│ 墓地 除外 额外 │  ── 共享额外怪兽区（2 格，谁的就朝谁）── │  徽章         │
│ （数字）       │  我方 怪兽行(5)                        │  对手牌堆计数 │
│               │  我方 魔陷行(5) + 场地                 │               │
└───────────────┴───────────────────────────────────────┴───────────────┘
```

* **卡面＝完整卡图**（萌卡那套中文卡面，见下"卡图"一节）+ 我们叠的**一个角标**：
  下面大号攻守（`2800/2100`、连接怪 `2000/LINK-2`）。卡图自带的卡名/星级/效果文字**不再重画**
  （用户口径 2026-10-09："去掉星级"、"不用写效果这类"）；**守备表示整张卡转 90°**（和 MD 局内一致）。
* **牌堆计数**：每侧画 墓地 / 除外 / 额外 三个数字（`fieldstate` 逐次移动维护的那三个计数）。
  **卡组张数不画**——对手的构筑是隐藏信息，内核不给；
* **里侧的卡只有卡背**（硬约束，见下）；没有卡图的卡画"无卡图"卡名框（不留白），
  连卡名都查不到就显示卡号。

## 四条硬约束（改这块时别越过）

1. **里侧一律画卡背**：图会发到群里，画卡面等于替对手公开信息。
   `tests/test_field_image.py::test_face_down_card_never_reveals_art_or_name` 钉着这条；
2. **缺图要兜底**：新卡/DIY 卡没有卡图时画卡名框，不能留白；
3. **卡图用真 `<img>`**（配 `wait_until="networkidle"`）：**别改回 CSS 背景图**，那样截屏会拍到
   还没解码的空卡面（用户 2026-10-07 报的"很多时候没有渲染成功就发出来了"）；
4. **出图绝不顶掉查房**：拿快照 / 渲染 / 发送任何一步失败都只记一条 warning，
   **退回纯文本**（`plugin.py` 的 `_send_field_image` 返回 False，`cmd_field` 走老路径）。

## 跑法

```bash
# 预览（不需要房间）：出一张演示局面，顺便用本机 Edge 渲染成 PNG
#  ⚠ 渲染要 playwright：用宿主那套 Python（<一键包>/python-env/python.exe）
<一键包>/python-env/python.exe tools/field_image.py --demo --render \
    --art-dir "D:/Game/MDPro3/Picture/Art" --art-fallback "D:/Game/MDPro3/Picture/Closeup" \
    --out temp/field-demo.html

# 群里：直接 /查房（本流房间发图；别处还有房间就补一段文字）
```

渲染链条：`duel/field_image.py` 生成 HTML（卡图内联成 data URI）→ 宿主的
`render.html2png`（Playwright + 本机 Edge，`device_scale_factor=2`）→ `send.image`。
两个能力都要在 `_manifest.json` 里声明（已加）。

## 卡图：完整卡图 + 自动预热（2026-10-08 ~ 09）

卡面按这个顺序取：

1. **完整卡图**（`<插件>/temp/card_pics/<卡号>.jpg`，本机缓存）——用户口径 2026-10-09：
   "卡图就直接用完整卡图，不用你做的立绘加卡框了……上面加上星级，下面直接写攻击力守备力就行"；
2. 缓存里还没有 → 画**兜底卡面**：名字（自动定字号/行数，保证完整显示）+ 星级 + 攻守，
   **不画立绘、不写效果**；后台会去补，补上之后下一次出图就是完整卡图；
3. 里侧一律卡背（硬约束，见下）。

**自动预热**（`duel/recorder.py` + `duel/card_images.py`）：卡一有动静（召唤/放置/移动/改表示形式）
就把它的整卡图排进**后台单线程池**——缓存里有就跳过、没有才联网（走 `netguard`：只 https/公网、
限 1 MiB、先写 `.part` 再原子替换）。所以等群里问 `/查房` 时缓存里基本都已经有了，
出图不用等下载、也不会出现"这格没卡图"。重复卡号只排一次，一局下来通常十几次请求。

⚠ **`view_from_state` / `to_card_view` 的 `pic_dir` 默认值就是这份缓存目录**（2026-10-09 修）：
线上 `/查房` 那条链路**不传**这个参数，默认 `None` 会让整张图全退化成兜底卡面
（用户实测："卡图没有正确渲染"）。别改回 `None`，测试 `test_view_defaults_to_warmed_cache_and_guesses_opponent_deck` 钉着它。

**对面的卡组名**（`FieldState.seen_ids()` + `_archetype_guess()`）：内核**不给**对面的构筑，
所以按"双方见过的卡名"猜一个主题词——统计 2~4 字片段里"出现在 ≥3 张**不同**卡"且（命中张数, 长度）
最大的那个（「卡通目录 / 完美世界 卡通世界 / 卡通黑魔术师」→「卡通」；「闪刀姬=零露 / 闪刀起动-连刀」→「闪刀」）。
猜不出来就只写"已见 N 张"，图上标的是 `卡通（看牌猜，已见 12 张）` 这种，**不假装是真名**。

* 想临时关掉联网补图（离线/测试）：环境变量 `MAIPLAYYGO_NO_PIC_FETCH=1`（`tests/conftest.py` 里默认打开）；
* 缓存目录在 `temp/` 下（gitignore），删掉就重新下；预览时 `tools/field_image.py --demo --render`
  会**同步**补一次（`--no-fetch` 可关，`--pic-dir` 可换目录）。

## 数据从哪来

* **格位与表示形式**：`duel/fieldstate.py` 的 `zones_of(seat)`（`(区域, 序号) → ZoneCard`）。
  表示形式来自 `MSG_SUMMONING/SPSUMMONING/FLIPSUMMONING`、`MSG_SET`、`MSG_MOVE` 与
  **`MSG_POS_CHANGE`**（2026-10-07 才接上：原来翻牌/改守备在台账里看不见）；
* **牌堆计数**：同文件的 `_move` 逐次维护（进、出都算，所以是"现在几张"），
  抄进 `PlayerField.grave / banished / extra`；
* **卡名 / 卡种 / 种族类型 / 攻守 / 等级 / 卡文**：`duel/cards.py` 的 `CardDatabase.card_details`（读 `cards.cdb`）；
* **LP / 回合 / 阶段**：记录器（阶段是 2026-10-07 起记的 `recorder.phase`）；
* **谁在行动**：`recorder.first_player_seat` + `turn_count` 的奇偶。
