# 训练功能细则（面板「训练台」）

README 上只留了"四件事"的表格；这份写**为什么这么做**与**踩过的坑**，改代码前先读它。

任务都在插件自带的面板里发起（`http://127.0.0.1:17911/`，训练台那一页），群里不加命令。
每个任务跑完，记录里都会有一段**明文结果**（`summary.result_text`）——数字是插件从工具输出里
抄的确定性事实，模型的结论另存 `summary.conclusion`（模型失败也不影响明文结果）。

## 一、四件事各自干什么

| 任务 | 流程 | 产出落在哪 |
| --- | --- | --- |
| 卡组互打 | 起两套内核+WindBot，两边各用自己那份脚本，逐局交替座位，最后打 Wilson 区间 | `logs/*-arena.log`、记录里的 `result_text` |
| 编写脚本 | 推 combo → （可选）联网查资料 → 分批写 C# 处理函数 → `dotnet build` | `Game/AI/Decks/<style>Executor.cs`、`train/combos/`、`train/research/` |
| 卡组迭代 | 每轮：推 combo → 写脚本 → 跟基线脚本打一轮（默认 20 局）→ 让模型读"脚本源码 + 逐局战况"写下一版改什么 | 同上 + 每轮的 `conclusion` |
| 复盘优化 | 读最近几局记录 + 当前脚本结构摘要/源码 + 那一局的 WindBot 决策日志 → 指出该改哪个函数/分支 → 给补丁（可选落地） | `train/reviews/*.txt`、补丁与落地结果都在记录里 |

## 二、复盘的四层材料（2026-10-09 补齐）

原来只有"对局统计"，于是模型只能看出症状、说不出该改哪一行；现在是四层：

1. **对局统计**：插件在每局结束时写的记录（回合、双方动作数、用过的卡、落位）。**不用录像**：
   `.yrp` 只有玩家的应答、没有内核的提问，逐动作复盘做不出来。
2. **脚本结构摘要**（`train/review_material.py::script_digest`）：规则注册顺序（＝优先级）、
   `OnSelectCard` 已经处理了哪些 `HintMsg`（**没列的＝会掉进 default**）、override 与规则函数签名、
   卡号常量，最后才是作者写的头部说明。按"排查时最有用"排序，每段各自截断、**不整段丢**
   （整段丢等于没给，模型只能回"这里被截断、无法判断"）。
3. **脚本源码片段**：补丁要照着它抄原文。
4. **最近那一局的 WindBot 决策日志**：内核问了什么、脚本选了谁。两个坑：
   * 对局记录是**打完那一刻**建的（`started_at`/`created_at`/`finished_at` 三个戳完全一样），
     窗口要往前推 `duration_seconds`——算反了只切到 2 行；
   * 插件每热更新一次就换一个 `app_*.log.jsonl`，不能只扫最新几个文件（按改时间挑"可能覆盖这一局"的）。
   前提是 `duel.bot_debug = true`（把 WindBot 的每步决策写进宿主日志）。

## 三、补丁与落地（`train/patchwork.py`）

复盘会要求模型给这种格式的补丁：

```
<<<PATCH
文件: XxxExecutor.cs
原因: 一句话
原文:
<与源码一字不差、且全文件只出现一次的一段>
改成:
<替换后的那段>
PATCH>>>
```

面板上勾「落地补丁」才会写进 WindBot 源码树并编译，语义是：

* **全有或全无**：有一个补丁对不上（原文 0 次或 2 次）就整批不落地，并说清是哪一条；
* **先留备份** `<文件>.bak-<时间戳>`，写回**逐字节保真**（BOM 与换行都不动，
  否则"留档副本 vs 源码树"的哈希会对不上）；
* **编译不过自动回滚**（把源码树留在编译不过的状态比"没改"更糟）；
* **有房间在打时只写不编译**（正在跑的 WindBot 锁着 `bin/Release/WindBot.exe`，编译必失败）。

默认不勾：模型给的建议可能是错的（**错误但能编译**的补丁也会落地），落地前后用 `git diff`
或备份对照一下更稳。

## 四、联网写脚本

`llm.search_model` 填一只**带检索**的模型后，写脚本/迭代会先让模型拿 `web_search` 工具自己查
（`search_rounds` 控制最多几轮；0＝退回"问一次那只联网模型"）。资料存 `train/research/`，
里面连"实际查了什么"一起写。提示词里写明**卡文与卡表是唯一依据**。

⚠ 两条实测结论：①不是每只模型都能联网（很多厂商的官方 API 只有纯生成），选之前先拿一句
"最近一个月有什么新公告"试它；②**联网不保证脚本更强**——同卡表对照 40 局，联网版与不联网版
分不出高下（读数见 `executors/README.md` §3.7）。

## 五、纪律与坑

* 训练任务**同一时刻只跑一个**；"房间里有人在打"时拒绝启动会抢资源的那些。
* 停任务会**连子孙进程一起杀**（Windows `taskkill /F /T`），否则孤儿内核会占着端口。
* 判强弱要 ≥80 局/腿（本机实测同一构筑重测会出现 0/60 与 8/20 并存的噪声）；20 局的迭代只看"机制有没有坏"。
* **面板怎么点都不会重启插件**；只有改插件目录里的 `.py` / `_manifest.json` 才会重启插件运行时
  （会掐断正在打的对局，也会让训练任务记成"被中断"）。
* 结果都落盘：`<工作目录>/training.db`（记录）、`logs/`（原始输出）、`combos/`（推演）、
  `research/`（联网资料）、`reviews/`（复盘存档）、`decks/`（从录像导出的卡表）。
